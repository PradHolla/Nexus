## Nexus Prod Plan v2: Qdrant Cloud + Hybrid Search + Quality/Ops Bundle

  ### Summary

  - Keep the previous AWS production architecture and keep Qdrant Cloud.
  - Add a production hybrid retrieval pipeline: dense + sparse fusion + reranker.
  - Keep API behavior backward compatible while adding non-breaking retrieval diagnostics and controls.
  - Target unchanged: FERPA-ready baseline, single-region pilot, 200 concurrent quiz generations, hard budget guardrails.

  ### Implementation Changes

  - Hybrid Retrieval (core)
      - Move to one multi-vector collection in Qdrant Cloud with named vectors: dense (Titan) + sparse (sidecar sparse model), plus existing payload metadata.
      - In ingestion workers, generate and upsert both vector types per chunk; keep deterministic point IDs and idempotent re-upserts.
      - Query path for each planner query:
          - Prefetch dense top-N and sparse top-M with strict tenant/course/file filters.
          - Fuse with Qdrant RRF.
          - Apply cross-encoder rerank on fused candidates; select final context window.
      - Add retrieval fallbacks:
          - If sparse retrieval is unavailable, degrade to dense-only + rerank.
          - If reranker times out, return fused results directly with quality flag.
  - Quality + Ops bundle (mandatory v1)
      - Prompt/version registry for planner/generator/critic prompts and model routing config.
      - Eval gates in CI/staging (faithfulness, answer relevance, context precision, retrieval hit-rate/NDCG).
      - Redis semantic cache for repeated professor prompts (short TTL + tenant/course scoped keys).
      - Cost-aware model routing with hard throttles/quotas at tenant and global levels.
      - Full observability: trace IDs across API -> queue -> workers -> Qdrant/LLM calls; SLO dashboards and alerts.
  - Platform/Data hardening (unchanged base, explicit)
      - FastAPI SSE on ECS Fargate behind ALB; heavy ingestion/retrieval in queue-driven workers.
      - Qdrant Cloud multitenancy pattern: payload partitioning with indexed tenant key and no per-course collection explosion.

      - max_context_chunks
      - include_retrieval_diagnostics (default false)
  - Add optional SSE diagnostic events when requested:
      - fused candidate counts, rerank latency, fallback mode used.
  - Keep frontend behavior unchanged if new fields are omitted.

  ### Test Plan

  - Retrieval quality
      - Golden-query suite comparing dense-only vs hybrid: NDCG@k, Recall@k, context precision.
      - Validate tenant isolation under hybrid filters (no cross-tenant hits).
  - Generation quality
      - RAG regression suite with acceptance thresholds for faithfulness/relevance before deploy.
  - Load/reliability
      - 200 concurrent generation load test with SLO checks.
      - Failure drills for sparse model outage, reranker timeout, and Qdrant transient errors.
  - Security/compliance
      - RBAC negative tests, audit-log completeness checks, quota/throttle enforcement tests.

  ### Assumptions and Defaults

  - Dense embeddings stay on Bedrock Titan; sparse vectors generated by worker sidecar (SPLADE-class sparse encoder) and stored in Qdrant.
  - Fusion algorithm default: RRF; reranker default: current cross-encoder path unless explicitly upgraded.
  - Qdrant Cloud is the production vector store (single cluster, payload-based multitenancy).
  - Backward compatibility is required for current frontend contract.
